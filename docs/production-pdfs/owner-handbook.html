1. What You Are Running

Frontend responsibilities

  • Landing page and auth screens
  • Dashboard, problem list, battle, leaderboard, solve view
  • Browser-side API calls to the backend

Backend responsibilities

  • User signup and login
  • Problem retrieval, code run, code submit
  • Battle state and leaderboard logic
  • AI coach fallback and optional OpenAI integration

2. Daily Operating Routine

Time Action Expected result
Morning Open the live website and test homepage, login, and one API-backed page. No frontend errors, pages load, API responds.
After each deploy Test signup/login, problem listing, run code, and submit code. Core user flow still works end to end.
End of day Review Render logs and Vercel deploy status. No repeating crashes, build failures, or route errors.

3. Weekly Operating Routine

  • Check MongoDB Atlas metrics for connection spikes, slow queries, and storage growth.
  • Review recent user-reported bugs and classify them as frontend, backend, or data issues.
  • Export or snapshot important production data before any structural change.
  • Verify that environment variables in Render and Vercel still match the live domains.

4. Launch-Day and Post-Deploy Checklist

  1. Push code to GitHub.
  2. Confirm Render backend deploy finishes successfully.
  3. Confirm Vercel frontend deploy finishes successfully.
  4. Open the live site and perform manual smoke tests.
  5. Check browser console and network tab for failing API calls.
  6. Check Render logs for startup errors, MongoDB failures, and CORS errors.

Smoke tests

  • Homepage loads
  • Signup works
  • Login works
  • Problems page loads
  • One problem can run and submit
  • Leaderboard loads
  • Battle page loads

Live configuration

  • Vercel: NEXT_PUBLIC_API_BASE_URL must point to Render
  • Render: CORS_ORIGIN must exactly match the Vercel domain
  • Render: MONGODB_URI must use current Atlas credentials
  • Optional: OPENAI_API_KEY only if AI coach is enabled

5. Where To Debug First

Symptom Check first Likely cause
Frontend loads, but buttons fail Browser network tab Bad API base URL, CORS, backend route error
Backend route returns 500 Render logs Unhandled server error, bad request body, DB issue
Signup/login broken Render logs and MongoDB Atlas DB auth, route logic, invalid env setup
Everything becomes slow Render instance status and Atlas metrics Cold starts, DB load, repeated heavy route execution

6. Incident Runbooks

A. Login or signup stops working

  1. Open browser devtools and inspect the failing request.
  2. Check HTTP status code and response payload.
  3. Open Render logs and find the matching time window.
  4. Verify MongoDB Atlas is reachable and credentials still work.
  5. Verify frontend is calling the correct backend URL.

B. CORS error appears in the browser

  1. Open Render environment variables.
  2. Check CORS_ORIGIN exactly matches the frontend URL protocol and domain.
  3. Remove stale domains if you want a locked production setup.
  4. Redeploy backend if Render does not auto-apply changes.

C. Backend crashes on deploy

  1. Read the top stack trace in Render logs.
  2. Check missing dependencies, bad import paths, and env variables.
  3. Check whether the backend root directory is still backend.
  4. Rollback or redeploy the previous stable commit if needed.

D. Website is slow

  1. Verify whether the delay is the first request after inactivity.
  2. If yes, treat it as a Render cold start risk.
  3. If not, check backend logs and Atlas metrics for sustained load or route hotspots.
  4. Test the exact slow route directly against the backend URL.

7. Data Ownership and Safe Changes

What is user data

  • Users
  • Passwords
  • Submissions
  • Battle outcomes
  • Profile changes

What is product data

  • Problems
  • Study plans
  • Tags and metadata
  • Seeded platform defaults

Before changing data

  • Take a backup or export
  • Test on a safe dataset
  • Deploy small changes
  • Verify results in production

8. Known Production Risks To Address Next

  • Passwords are stored in plain text. Move to hashed passwords with bcrypt before serious scale.
  • No automated tests. Add route-level smoke tests for auth and problem submission.
  • Cold-start risk on Render. Expect slower first requests on lower tiers.
  • OpenAI coach depends on env setup. Missing API key is okay, but behavior should stay intentional.
  • MongoDB credentials were exposed in a screenshot earlier. Rotate them immediately and update Render.

9. Support Tools You Will Use Most

  • Vercel dashboard: frontend deployments, env vars, build failures
  • Render dashboard: backend logs, deploy history, runtime env vars
  • MongoDB Atlas: cluster health, database users, metrics, backups
  • Browser devtools: console errors, network failures, bad API payloads
  • GitHub: code history, rollback point, deploy source of truth
