Creation

  • User signs up
  • User submits solution
  • Battle gets created
  • Problem set gets seeded

Persistence

  • MongoDB Atlas stores users, problems, submissions, battles, study plans
  • Mongoose models define application-level structure

Read path

  • Frontend requests dashboard or problem routes
  • Backend queries Atlas and returns JSON

Recovery path

  • Take backups before risky changes
  • Restore from Atlas backup or exported dataset
  • Redeploy known-good code if the bug is code-driven
